Frequently Asked Questions

Everything you need to know about AVFA academic verification and cryptographic integrity.

How does AVFA prevent Photoshop / document editing fraud? +
AVFA uses a dual-layer security model. First, every issued degree has a canonical SHA-256 hash signed with the university's RSA-2048 private key. Second, when a PDF is uploaded in Tab B, our PyMuPDF & RapidFuzz OCR engine extracts the text and cross-references each field against the official ledger, highlighting any altered marks, CGPA, or names in bright red.
What happens when a university revokes a certificate? +
Revocation is instantaneous worldwide. When an authorized official revokes a credential from the dashboard, its state is updated on the immutable ledger. Any subsequent QR scan or ID lookup immediately flashes a bright red "Revocation Warning" with the audit reason and timestamp.
Can a fake candidate use another student's real Certificate ID? +
No. When a verifier searches the Certificate ID, AVFA retrieves the official student name and roll number directly from the university registry. If the candidate's resume says "Rohan" but the registry says "Vansh", the identity mismatch is exposed in under 1 second.
Is student data secure and compliant with privacy standards? +
Yes. AVFA enforces Row-Level Security (RLS) in PostgreSQL, blocking unauthorized public database access. Sensitive operations require JSON Web Token (JWT) authorization and cryptographic Two-Factor OTP authentication.
What is the Blockchain Ledger Synchronization badge? +
The green "Ledger Synchronized" badge in the navbar indicates that all issued credentials are mathematically anchored in an immutable Merkle block chain. Clicking the badge opens the live consensus explorer showing total anchored blocks and hash integrity.

Security Architecture

The AVFA 4-Step Verification Pipeline

How academic records transition from university issuance to tamper-proof public verification.

1

Institutional Ingestion & 2FA Auth

Accredited universities authenticate with two-factor email OTP to access the issuing engine for single or batch graduate records.

2

Canonical SHA-256 Serialization

Graduate details, marks obtained, total score, CGPA, and timestamps are structured into a deterministic canonical payload and hashed.

3

RSA-2048 Asymmetric Signing & PDF Generation

The university signs the canonical hash using its private key, rendering a vector PDF with an embedded high-density verification QR code.

4

Public Dual-Mode Verification

Verifiers validate credentials in sub-seconds using Tab A (Camera QR scanner / ID search) or Tab B (Forensic PDF Upload with RapidFuzz micro-tampering analysis).
